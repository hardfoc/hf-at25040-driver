inlinenoexcept

READ len bytes starting at addr (sequential read, any length).

The chip increments the address after every byte (datasheet 8707F, section 6, "Read Sequence"), so one READ can stream the whole array. The driver splits the request into READ transactions of at most kReadChunkBytes data bytes, so a port never sees more than 2 + kReadChunkBytes bytes, and recomputes A8 for each one.

Returns
Status::Arg for a null dst, len == 0 or a range past 0x1FF (no transfer is made; the chip would roll over to 0x000). Status::Busy if RDSR shows a write cycle in progress (the chip would ignore the READ; nothing is read). Status::BusError if a transfer failed: the bytes of the chunks before it are in dst.

◆ SetBlockProtection()

template<typename Spi >
Status at25040::Device< Spi >::SetBlockProtection ( BlockProtect  level)
inlinenoexcept

WREN + WRSR: set BP1:BP0 (datasheet section 6, Write Status Register, Table 6-4), then wait for the write cycle: the bits are non-volatile and take tWC like a WRITE.

WP must be high; the chip ignores WRSR otherwise. Read the level back with GetBlockProtection() if it matters.

Returns
Status::Arg for a value outside BlockProtect, Status::Busy if a write cycle was already running, Status::BusError if a transfer failed, Status::Timeout if the write cycle did not end in time.

◆ WaitReady()

template<typename Spi >
Status at25040::Device< Spi >::WaitReady ( uint32_t  timeout_ms = kWriteCycleTimeoutMs)
inlinenoexcept

Poll RDSR until RDY (bit 0) reads 0: the internal write cycle has ended.

The chip ignores every instruction except RDSR during a write cycle, and RDY = 1 while it runs (datasheet section 6, Write Sequence, and Table 6-3). If the port has an optional void delay_us(uint32_t us) member, the driver waits kPollIntervalUs between polls; otherwise it polls back to back, kPollsPerMsWithoutDelay times per millisecond of timeout_ms.

Parameters
timeout_msBudget; the default covers the 5 ms maximum tWC with margin.
Returns
Status::Ok when ready, Status::BusError if a transfer failed, Status::Timeout if RDY was still 1 (also what a floating MISO, which reads 0xFF, looks like) at the end of the budget.

◆ WritePage()

template<typename Spi >
Status at25040::Device< Spi >::WritePage ( uint16_t  addr,
const uint8_t *  src,
uint16_t  len 
)
inlinenoexcept

WREN + WRITE of 1 to 8 bytes inside one 8-byte page, then wait for the write cycle.

Only the three low address bits increment during a WRITE, so bytes past the end of a page would wrap to its start (datasheet section 6, Write Sequence, p. 9): a range that crosses a page is refused. Programming starts when CS goes high; the call then polls RDSR (WaitReady()) and returns when the chip is ready again, so the next call is not ignored.

Returns
Status::Arg for a null src, a length of 0 or above kPageSizeBytes, a page crossing or a range past the array (nothing is sent). Status::Busy if RDSR shows a write cycle already in progress (nothing is written). Status::BusError if a transfer failed; Status::Timeout if the write cycle did not end within kWriteCycleTimeoutMs.

constexpr uint32_t at25040::Device< Spi >::kPollsPerMsWithoutDelay = 1112
staticconstexpr

RDSR polls per millisecond of WaitReady() budget when the port has no delay_us(). One RDSR is 16 SCK periods plus tCS: 0.9 us at the 20 MHz maximum clock (datasheet Table 4-3), so this many polls last at least 1 ms on any legal bus; on a slower bus the wait is proportionally longer.
